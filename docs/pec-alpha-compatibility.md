# Отрицательная alpha исходного PEC

В PhiStudio 1.0.6 конвертированный PEC сохраняет `META.phiPecAlphaExtension=true`.
Этот признак восстанавливается при открытии JSON, сохранении рабочего пакета
и повторном импорте экспорта PhiStudio. Другие поля META сохраняются отдельно.
У обычного RPE признак отсутствует и прежнее правило отрицательной alpha
остаётся прежним: скрываются линия и геометрия нот, judgement effects продолжаются.

Для PEC положительные значения переводятся в нормализованные f32 до
интерполяции, отрицательные значения остаются исходными флагами. Tween выполняет
`from + (to - from) * progress` в f32. Скалярное значение возвращается в единицах
0..255 для положительной alpha и без масштабирования для отрицательной.
Например, `ca 0 0 -255` и `cf 0 1 2 255` дают -127 на 1.5 с и 255 на 2 с
при BPM=60; интерполяция авторских -255..255 дала бы другое поведение.

При отрицательной alpha применяется `floor(-alpha)` из исходного
`prpr/src/core/line.rs`:

| Флаг | Видимость нот |
| --- | --- |
| 1 | Линия и геометрия нот скрыты |
| 2 | Включён cover, то есть `draw_below=false` |
| 100..999 | Ноты появляются за `(flag - 100) / 10` **битов** до попадания |
| Остальные | Дополнительное скрытие не применяется |

Alpha самой линии при отрицательном значении равна нулю. Флаги 1000..1999
не реализуют дополнительного поведения и в выбранном upstream помечены TODO.
Кэш подготовленного playback учитывает происхождение PEC, включая смену
признака без `markEdited()`.

Скалярные ожидания в `pec-alpha-values.csv` получены отдельным исполнением
полного исходного Rust PEC parser и AnimFloat. `pec-alpha-provenance.json`
содержит контрольные суммы PEC, Rust-источников, executable и дампа. Проверки
сравнивают 121 значение до/после сохранения, конфигурацию видимости, геометрию
нот в CPU-сцене PhiStudio и save/reopen/export рабочего пакета. Полная сцена
Phira и реальные GPU-кадры этими тестами не исполняются.

Сохранённый RPE JSON имеет ограничение совместимости с **нативным Phira**:
его `parse/rpe.rs` игнорирует `phiPecAlphaExtension` и создаёт
`ChartSettings::default()`, где PEC extension выключен. Отрицательная alpha
там нормализуется как обычная RPE opacity, а не интерпретируется как PEC-флаг.
Поэтому сохранение и повторное открытие в PhiStudio сохраняют PEC-семантику,
но экспорт в RPE не доказывает такую же семантику при открытии в Phira.

Если нужен совместимый с нативным Phira экспорт этих флагов, нужен отдельный
режим PEC: он должен сохранять или восстанавливать исходные команды, а также
явно обрабатывать изменения, которые нельзя выразить в PEC. Этот режим здесь
не добавлен; custom META не используется как доказательство совместимости
нативного RPE parser.
