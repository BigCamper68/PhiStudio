## Note source in Preview

The requested feature identifies the judge line owning a note seen in the
gameplay preview. The supplied discussion describes click-to-select-line and
hover-to-show-origin. The public behavioral reference inspected here is
[RPE-Next](https://github.com/kclg-YSJ/rpe-next/blob/6ccdbd0e2d0f3f5891cb79a4726247f8077c12d1/src/ui/app.mjs):
its preview click selects a picked note's line, and a delayed hover displays
the source line. This is not a claim to have found the original desktop
RPE's source. PhiStudio implements the behavior in its existing Android editor.

In full-screen Preview:

- A tap selects the exact source note and its judge line, preserving Preview,
  the current time and playback state. The bottom status strip shows the raw
  zero-based line ID, name, one-based source note number and authored beat.
- The existing Editor toolbar button becomes **Edit note**. It or the source
  strip pauses playback, returns to the Event editor and selects the source
  note at its authored beat. Existing note properties and editing actions apply.
- A long press or delayed mouse/stylus hover shows origin without selecting a
  different line. Hover leave, cancellation and a second finger cancel pending
  hints. Pointer hover can move onto the source strip to follow it.
- A drag continues to scrub. Small finger wobble within the platform touch
  slop does not accidentally seek or place an edit command.

Navigation is read-only: no note/line is moved or created, no chart revision or
Undo command is added. Source references are checked before navigation; project
replacement, removed notes and changed line identities cannot target another
object occupying the same list position. Pending callbacks reset on context
changes and detachment.

## Picking and rendering

Each sampled render note now retains its original Note identity. Its sampled
geometry remains independent of later mutations of that source object.
Picking uses the renderer's coordinate projection, note textures, Phira note
scale, size controls, above/below side, inclination and rotation. It reverses
the actual global note-type/line/note draw order, and prefers an exact visual
rectangle hit over the small finger tolerance. Clip/visibility checks exclude
black borders, hidden or zero-size notes and fully offscreen rectangles.

Hold bodies, heads and tail caps are separate rectangles. Active holds without
a head and negative-speed holds without a body do not acquire an invisible
clickable body between caps. The same sampled geometry already includes parent
line transforms and chart note controls.

The shader TextureView retains the scene, viewport and settings of its last
accepted Canvas frame while the GPU is busy. Picking uses that snapshot rather
than a newer scene whose buffers were not submitted. Navigation and hint chrome
stay outside the shader surface. Picking follows pre-effect note geometry;
arbitrary shader warping is not inverted. Playtest judgement remains independent.

Robolectric Android 8/API 26 and Android 14/API 34 exercise picking order,
finger tolerance, clipping, scale, mirrored notes, rotated holds, negative-speed
caps, source identity, tapping, long press, hover, cancellation, multiple
pointers, audio scrub/resume, exact editor navigation and stale targets. An
accepted GPU snapshot test verifies that geometry remains frozen when its
source Note is edited, and that hiding the surface drops its navigation cache.
These are not a physical-device or live EGL test.

The existing grid and Noise Field gesture/layout suites run alongside the new
checks. Full ARM64 validation retains its explicit native-graphics exclusions
and unavailable-chart skips. Packaging records source fingerprints, translated
resources, APK version/signature and exact source archive/patch reconstruction.
