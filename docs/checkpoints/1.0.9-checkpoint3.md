# PhiStudio 1.0.9 checkpoint 3

Based on checkpoint 2, `de36c32cf35ef8d4fc6a333546750a2a0b5fa022`.
The Micrology clipping fix and native noise field rendering are retained.

## Music low-pass

In Playtest an infected noise-field contact now filters music until release.
All contacts contribute: releasing one finger cannot restore music while another
infected contact remains down. The filter runs before scheduled hit mixing, and
manual hit sounds use their existing separate output. Pausing, seeking, Retry,
cancellation, resizing and leaving Playtest clear the touch/filter state.

The filter follows the 1500 Hz / 0.1 s serialized preset documented in
[Phira-Pro's native compatibility implementation](https://github.com/Phira-Pro/Phira-Pro/blob/b67e5e845b58e3cf89d674e782a9b3bd0f5e8af8/prpr/src/core/block_audio.rs)
and the enable/bypass behavior in the published
[ProgressControl decompilation](https://github.com/CHCAT1320/CHCAT-Docs/blob/054fcfdddc4ddf66b1bbecc45df0d5264e3d3852/knowladge/phigros/code/BlockRender.decompiled.md).
First entry uses the stored preset immediately; subsequent entries interpolate
the stored cutoff for 0.1 seconds. Release bypasses the filter immediately while
its stored cutoff moves toward 22000 Hz, as in the published control code.

Unity's internal DSP is not open here. PCM filtering uses a maximally flat
second-order biquad, Q=1/sqrt(2), from the
[Audio EQ Cookbook](https://webaudio.github.io/Audio-EQ-Cookbook/audio-eq-cookbook.html).
This is the same response choice as Phira-Pro; the native control transitions are
preserved without claiming sample-for-sample equivalence to Unity's private DSP.
Ordinary playback and released contacts use a bit-exact PCM bypass.

## Effects beneath the note grid

The translucent gameplay preview under the editor grid now uses the shared GPU
compositor when a shader or a noise field is visible. It retains the existing
illustration crop, brightness and 128/255 opacity. Grid lines, editable notes and
controls are drawn above the preview and keep their input ownership. Hit particles
remain above local shaders; the under-grid preview does not add a HUD.

Settings has a dedicated **Preview beneath the note grid** section:

- **Show shaders** — enabled by default.
- **Show noise fields** — enabled by default.

These switches are independent, persist across restarts, and apply only to the
under-grid preview. Fullscreen Preview, the shader editor, Playtest and video
export retain their effects. Intervals without enabled effects keep the existing
Canvas path. GPU frames stay in hardware buffers; there is no full-frame bitmap
readback/upload added to playback.

## Preview note scale

Settings → **Preview note scale (0.800–1.200)** defaults to **1.000**.
It applies to the under-grid preview, fullscreen Preview, shader-editor preview,
Playtest and video export. The note width used for timeline editing remains a
separate setting.

The calculation follows official
[Phira Resource/ParticleEmitter](https://github.com/TeamFlos/phira/blob/0afd16621dd66557841a8cffe6813afff63335ec/prpr/src/core/resource.rs)
and [note rendering](https://github.com/TeamFlos/phira/blob/0afd16621dd66557841a8cffe6813afff63335ec/prpr/src/core/note.rs):
the global scale multiplies the skin's note width, sprite height, hold cap sizes,
hit sprite/square sizes and particle travel. Hold body length, note positions,
authored scale events, timing and judgement areas are preserved.

## Validation

- PCM tests check 200 Hz preservation, 10 kHz attenuation at 32/44.1/48 kHz,
  independent stereo channels, exact bypass, release/reentry and block-size
  independence. An injected-output test runs the actual PCM player, checks the
  music-before-hit mixing order and verifies reset on seek/pause.
- UI and preferences tests cover defaults, both independent switches, note-scale
  limits, Apply/reopening, Canvas fallback, fullscreen isolation, under-grid bounds
  and the transparent editor window above a presented GPU frame.
- Canvas command tests check all note types and renderer entry points at 0.800,
  1.000 and 1.200, including signed authored scales, uniform scaling, hold body/caps,
  hit sprites and particle sizes/travel.
- The host JNI check executes production `ShaderGlRenderer` with real
  EGLImage-backed external textures on Mesa. Six constant-color frames check
  opacity at 1 and 128/255 in three sizes (within one 8-bit channel value), and 21
  real-field frames exercise Desultory Signals and repeated seeks.
- The full ARM64 suite includes both supplied chart regressions. Desktop native
  graphics tests excluded by `tools/termux-tests.gradle` are not counted as passed.

No ADB device was connected. Android HWUI/SurfaceTexture delivery, physical audio
output and hardware MP4 export still need a device check. The Mesa adapter does
not simulate those Android components.
