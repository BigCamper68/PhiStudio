# 1.0.9 checkpoint 9

Checkpoint 9 fixes MULTIPHEX export and adds the color protocol actually read by
Phira-Pro. Version code: 104. Base: checkpoint 8 (`44fe268d656a1670b122e0df97f7ebd260dcf84a`).

## Native serialization

`moveEvents`, `scaleEvents` and `rotateEvents` are stably sorted on save/export.
Equal-time keys retain their relative order. Original numeric precision, unknown
properties, editor indices and Undo/Redo snapshots remain intact. This covers
JSON, autosaves, workspace saves and package export. MULTIPHEX previously exported
scale keys in reverse order: Phira-Pro's binary search selected zero horizontal
scale throughout field 1. Field 2 also had reversed move keys.

## Compatible colors and export options

**Export package** opens a compact scrollable dialog on every export. Choose 3:2,
16:9, 4:3 or 21:9; the last choice is remembered. `info.yml` stores this copy's
`aspectRatio` and `forceAspectRatio`. The source package and editor viewport do
not change. Picker recreation preserves both the ratio and color target.

**Phira-Pro color fields** defaults on when native fields have custom RGB. It
converts all native fields together into the supported Line2Area representation:

- `isSubtract0.png` / `isSubtract1.png`, in a collision-free resource folder;
- `extended.colorEvents` with byte RGB, plus scale events and RPE transforms;
- speed event start codes 1/2/3/4 for appear/enable/disable/disappear;
- ordinary line IDs stay intact; no duplicate native `blockAreaList` is emitted.

The conversion samples the production native transform, including zero/negative
scale and changing anchors, with adaptive subdivision (0.025 canvas-pixel
parameter tolerance, maximum animated step 1/120 s). RPE event times use the chart
BPM map, without reapplying music offset. The native evaluator remains unchanged
for ordinary preview and export; collapsed geometry can now be sampled for baking.

**Projection limit:** native fields use screen percentages and rotate after
mapping to the screen. Phira-Pro colored fields rotate in a 1350×900 RPE canvas,
then stretch to the playback ratio. These geometries coincide at **3:2**. Other
ratios intentionally use the player's RPE projection; rotated fields need not
match the native screen-percentage preview. The export dialog explains this.
Color conversion requires ordered lifecycle phases; unusual native lifetimes
remain available through native export. A bounded animation sample budget reports
an export error rather than truncating a field.

The `phiStudioNoiseSource` extension retains original fields. SHA-256 fingerprints
of generated tracks and BPM data guard restoration: if another editor changes
the exported lines, PhiStudio keeps those edits as ordinary RPE tracks rather
than silently restoring stale originals. RGB on native fields is still saved as
`phiStudioColor`; merely renaming that property would not make Phira-Pro read it.

## Reading Phira-Pro fields

PNG header dimensions are read only for recognized marker textures, without
decoding their pixels during project load. The adapter handles signed scale,
image anchors, parent translations/rotations, animated color, lifecycle codes
and the alpha fallback. RPE canvas stretching applies after rotation. Guides
do not draw over the chart. The same geometry feeds full preview, under-grid
preview, video and Playtest touch infection/audio filtering.

External Line2Area tracks remain editable in Event/Storyboard; exports generated
by PhiStudio restore to the usual Noise Field editor when the fingerprint matches.
This is the legacy RPE Line2Area protocol, not full support for unrelated RPEN
extensions or a promise of support in the unmerged official Phira noise-field PR.
