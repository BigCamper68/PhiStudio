# 1.0.9 checkpoint 10

Version code 105; base checkpoint 9 (`20c43616372f1ef15ea295d3983fd4b31126ebf6`).

## Empty noise-field timeline on Android

Checkpoint 9 exported native fields as Phira-Pro Line2Area tracks and retained
editable source fields behind fingerprints. Its fingerprints depended on JSON
text conventions: Android parses integer `-0` as positive zero and quotes `/`
differently from desktop org.json. Valid exports therefore failed restoration
on Android. They rendered as RPE markers but were absent from Noise Field.
The previous plain-JVM package tests did not catch this platform difference.

A reproduction against the actual delivered checkpoint 9 MULTIPHEX failed on
both Robolectric Android 8/API 26 and Android 14/API 34 before the fix: zero
editable fields instead of two, plus a failing signed-zero fingerprint test.
Both field count and actual timeline hit blocks are now checked.

Version 2 transport fingerprints hash typed values, sorted keys, UTF-8 strings
and normalized IEEE-754 numbers; JSON escaping and the sign of zero are ignored.
They still distinguish changes to motion, RGB, phase codes and BPM data.
Version 1 imports support both previous codecs and preserve signed-zero wire
tokens. Already-saved broken checkpoint 9 projects can recover through a guarded
comparison with regenerated tracks after normal model serialization; real
external edits are preserved rather than replaced with stale native fields.

Recovered packages immediately save native editable fields into their private
project workspace. Original imported ZIPs are unchanged. Later project opens
use the normal field model and do not repeat transport validation or rebaking.
Undo/Redo, unknown field properties, key precision and audio assets remain intact.

## Ordinary export

The aspect-ratio/color dialog, its pending picker options and its preferences
are removed. Export package goes directly to the Android file picker. Custom
field colors automatically select the compatible representation; uncolored
fields continue to use native `blockAreaList` with sorted keys. Package aspect
ratio and forced-aspect settings are preserved, without adding new ones.

The compatible file uses `colorEvents`, marker PNGs and lifecycle codes supported
by the published [Phira-Pro pro.16/build 82 release](https://github.com/Phira-Pro/Phira-Pro/releases/tag/v0.8.2-pro.16).
Its `rpe_block.rs` is identical to the implementation checked in checkpoint 9.
This does not change Phira-Pro's RPE canvas projection: native screen-percentage
rotation and RPE canvas rotation coincide at 3:2; other viewports can project
them differently. No new format selection is added to the export flow.

## Checks

Android regressions use the original MULTIPHEX ZIP, the exact issued checkpoint 9
ZIP and a newly exported package. They check two white editable fields, timeline
blocks, deletion with Undo/Redo, export/import, native workspace reload, absence
of an extra export dialog, unchanged aspect metadata and byte-identical audio.
Legacy recovery also checks that a real external RGB edit is retained.
Canonicalization tests cover signed zero, numeric types, escaping, Unicode,
object key order and preserved literal strings.

Set `PHISTUDIO_MULTIPHEX_CHART`, `PHISTUDIO_CHECKPOINT9_EXPORT`,
`PHISTUDIO_NOISE_FIELD_CHART` and `PHISTUDIO_MICROLOGY_CHART` to the supplied ZIPs.
`PHISTUDIO_ANDROID_EXPORT_OUTPUT` optionally collects the packages produced by the
Android codec tests. `PHISTUDIO_DESKTOP_EXPORT` supplies a version 2 desktop
export for the reverse cross-runtime regression. The Android-produced ZIPs are
also imported on the desktop and compared with the complete original chart and
audio. Checks record both the failing reproduction and passing
regressions. Robolectric and desktop checks do not constitute a physical-device
or complete external-player run; the ARM64 profile keeps its stated exclusions.
